# 从三个模型搭建关联裁剪工作流

本教程使用虚构的仓储质检场景，只讲通用结构。仓库不提供权重，示例名称、类别和参数与任何生产流程无关。

## 目标

假设有三个本地 ONNX 模型：

- `package_detector`：整图检测包裹，类别为 `package`、`crate`；
- `marker_detector`：整图检测标记，类别为 `label`、`seal`、`tag`；
- `detail_classifier`：处理裁剪图，类别为 `ok`、`damaged`、`uncertain`。

要实现的流程是：两个模型先处理整图；若标记中心点位于某个包裹框内，就裁剪该包裹；再把裁剪图送入分类模型。

```text
媒体输入
  ├─> 包裹检测 ──(subject)──┐
  └─> 标记检测 ─(candidate)─┤
                             v
                         空间关联
                             v
                       裁剪命中主体
                             v
                        裁剪图分类
                             v
                          结果预览
```

这对应 VideoPipe 一类节点管线的核心思路：每个模块只做一件事，节点之间通过明确的数据键连接；模型、规则和输出彼此独立。

## 第一步：登记模型

在模型库分别添加三个模型。类别表必须按模型输出索引填写。保存后逐个试跑。若输出框位置错误，优先检查输入尺寸、letterbox 和输出格式；若类别错位，检查类别表顺序。

## 第二步：用向导生成骨架

在工作流页选择“双模型关联 → 裁剪 → 下游”：

1. 主体模型选择 `package_detector`。
2. 候选模型选择 `marker_detector`。
3. 下游模型选择 `detail_classifier`。
4. 工作流名称填写自己的项目名称。

向导只生成草稿。进入节点画布后检查每一步参数。

## 第三步：配置关联规则

在“空间关联”节点填写：

- 主体结果键：`subject`
- 候选结果键：`candidate`
- 主体类别：`package,crate`
- 候选类别：`label,seal,tag`
- 关联方式：`center_inside`
- 阈值：`1.0`
- 主体扩边：`0.05`

关联方式的含义：

| 方式 | 含义 | 常见用途 |
|---|---|---|
| `center_inside` | 候选框中心是否落在主体内 | 小目标归属于大目标 |
| `ioa_right` | 交集占候选框面积比例 | 候选大部分被主体包含 |
| `ioa_left` | 交集占主体框面积比例 | 主体大部分处于某区域或容器 |
| `iou` | 交集与并集之比 | 两个大小接近的框是否对应 |

先使用容易解释的规则，再用真实验证集调参数。阈值变化应记录在工作流版本中。

## 第四步：配置裁剪和下游

“裁剪”节点选择 `associated`，表示只裁剪关联命中的主体。扩边比例可从 `0.1` 开始，最小面积先设为 `0`，确认流程正确后再过滤过小目标。

“裁剪图推理”路由设为 `all`，模型选择 `detail_classifier`。分类结果保存在对应裁剪槽的结果层中；若下游是检测模型，框坐标保存在裁剪图局部坐标中，并可映射回全图预览。

## 第五步：验证和保存

1. 选择一张无敏感内容的试跑图片。
2. 执行“运行前检查”。
3. 运行整条流水线，逐节点查看输入、输出数量和耗时。
4. 用至少四类样本验证：正常命中、无候选、多个候选、主体靠近图像边缘。
5. 保存工作流，再到视觉复核页检查裁剪图和下游结果。

## 更复杂的组合

在这个骨架上可以继续增加：

- 在关联前增加“类别筛选”，让规则只处理所需类别；
- 在主体检测后增加 ROI，排除画面外区域；
- 使用多个关联节点构造不同条件，再通过插件节点实现 AND、OR 或自定义打分；
- 增加多个裁剪推理节点，让同一裁剪图进入分类、检测或姿态模型；
- 把输出节点作为显式动作，避免试跑时意外写盘。

复杂逻辑建议做成独立插件节点。插件输入输出应使用通用 `Packet` 字段或 `meta` 命名键，参数放进工作流 JSON，避免把模型路径和业务值写死在 Python 中。
