# 快速开始

## 1. 安装环境

```powershell
git clone https://github.com/backward052/AnnoWeave.git
cd AnnoWeave
.\scripts\setup.ps1
```

`setup.ps1` 会自动寻找可用的 64 位 Python（3.10 – 3.13，推荐 3.12/3.13）、创建 `.venv`、安装 CPU 运行时与开发依赖、校验导入，并运行测试。

手动等价步骤：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -e ".[cpu]"
```

使用 NVIDIA CUDA 版 ONNX Runtime 时把 `cpu` 换成 `gpu`。不要在同一环境同时安装两个 Runtime 包。

启动方式：`.\scripts\run.ps1`，或在已激活的环境里执行 `annoweave`。

如果某一步失败，请对照[主 README 的常见问题表](../README_zh-CN.md#安装常见问题)。

首次启动时模型库和工作流都是空的。这个状态是有意设计的：公开版本不附带权重、类别表或生产流程。

## 2. 添加第一个模型

进入“模型库”，点击“添加模型”：

- **名称**：工作流引用标识，例如 `primary_detector`。保存后尽量不要改名。
- **类型**：按 ONNX 导出结构选择检测、分类或姿态类型。
- **模型路径**：选择本机权重。路径只保存在本机配置中。
- **输入尺寸与 letterbox**：应与训练和导出设置一致。
- **类别表**：按输出索引完整填写；顺序错误会导致显示类别错误。
- **阈值**：先用模型验证集建议值，再在真实素材上调整。

选中模型后执行“试跑选中模型”。“就绪”只表示依赖和文件可用；试跑成功才能证明模型可加载并完成一次前后处理。

## 3. 创建工作流

进入“工作流”，点击“创建工作流”。新手建议先用“多模型整图复核”验证模型，再使用“检测 → 裁剪 → 下游推理”或“双模型关联 → 裁剪 → 下游”。

保存前执行“运行前检查”，重点处理以下问题：

- 节点引用的模型不在模型库；
- 关联节点引用的结果键尚未生成；
- 裁剪节点之前没有主体结果或关联结果；
- 下游推理之前没有裁剪节点。

也可以导入仓库自带的示例：在工作流页使用“导入工作流 JSON”，选择 `examples/workflows/associate-crop-infer.json`。它是通用教学结构，不是可直接运行的流程 —— 需要先按其中的名称登记模型。

## 4. 打开素材并复核

在“视觉复核”点击“打开素材”，可以选择单个文件、多个文件或文件夹。视频按采样 FPS 产生采样帧；图片按一个复核项处理。

“运行当前帧”会重新执行当前工作流。若本帧已有人工修改，只有推理成功后才用新的模型结果替换，避免模型故障造成编辑丢失。修改全图框后，关联、裁剪与下游节点会按当前标注重新计算。

框编辑快捷操作：

- `V`：选择与移动；`R`：绘制矩形；`H`：平移。
- 鼠标滚轮：缩放；中键拖动：平移。
- `Delete`：删除选中对象；`Ctrl+Z` / `Ctrl+Shift+Z`：撤销 / 重做。
- `Tab`：在重叠对象间循环选择。

## 5. 保存与导出

普通浏览不会自动进入训练集。只有人工修改或明确加入保存集的帧，才应作为训练数据导出。复核产物适合查验，训练数据导出会生成原图/裁剪图与机器可读标签。导出前检查类别映射和输出目录，保留生成的清单用于追溯。

## 6. 数据存放位置

所有运行时数据默认写入 `%LOCALAPPDATA%\AnnoWeave`，不会进入 Git 仓库。如果想集中到一个自定义目录，在启动前设置 `ANNOWEAVE_CONFIG_DIR`：

```powershell
$env:ANNOWEAVE_CONFIG_DIR = "D:\AnnoWeaveData"
.\scripts\run.ps1
```
